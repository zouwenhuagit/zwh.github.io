# AI 使用与理解

> **目标**：系统掌握 AI 基础概念、核心技术、Agent 与 MCP，在 IDE 中高效使用 AI 功能

## 一、AI 基础概念篇

### 1.1 什么是人工智能（AI）？

人工智能（AI）是让计算机模拟人类智能行为的技术，包括学习、推理、感知、理解语言等能力。

### 1.2 机器学习 vs 深度学习 vs 生成式 AI

```
人工智能（AI）
  ├── 机器学习（ML）
  │   ├── 监督学习（分类、回归）
  │   ├── 无监督学习（聚类、降维）
  │   └── 强化学习
  ├── 深度学习（DL）
  │   ├── 卷积神经网络（CNN）
  │   ├── 循环神经网络（RNN）
  │   └── Transformer（革命性架构）
  └── 生成式 AI（GenAI）
      ├── 大语言模型（LLM）—— ChatGPT、Claude
      ├── 图像生成 —— Midjourney、Stable Diffusion
      └── 多模态 —— GPT-4o、Gemini
```

### 1.3 大语言模型（LLM）是什么？

LLM 是 "Large Language Model" 的缩写，指经过海量文本数据训练的大型神经网络模型。

**核心能力**：理解、生成、推理、总结。

### 1.4 机器学习三要素（技术视角）

1. **数据**：算法学习的原材料
2. **算法**：从数据中提取规律的模型
3. **算力**：支撑模型训练的计算资源

### 1.5 AI 产业三要素（应用视角）

三者缺一不可：有数据没算法，无法学习；有算法没数据，无从学起；有数据有算法没算力，学得太慢甚至学不动。

## 二、AI 核心要素篇

### 2.1 Prompt（提示词）—— 与 AI 对话的艺术

Prompt 是你输入给 AI 的指令，是决定输出质量的关键。

**基础 Prompt 结构**：
- **角色设定**：如"你是一位资深的 Java 工程师..."
- **任务描述**：如"请帮我写一个读取 CSV 文件的工具类..."
- **约束条件**：如"要处理空值，代码要加入日志..."
- **输出格式**：如"用 markdown 代码块返回..."

**高级 Prompt 技巧**：
- **Few-shot Prompting**（少样本提示）：给出几个示例，让 AI 模仿
- **Chain-of-Thought**（思维链）：引导 AI 一步步思考
- **System Prompt**（系统提示词）：设定 AI 的长期行为模式

### 2.2 RAG（检索增强生成）—— 让 AI 拥有"外挂知识库"

RAG（Retrieval-Augmented Generation）是一种技术框架：在 LLM 回答之前，先从外部知识库检索相关信息，然后让 LLM 基于检索结果生成回答。

| | 没有 RAG | 有 RAG |
|--|----------|--------|
| 知识来源 | 仅靠训练数据记忆 | 从最新文档/数据库中检索 |
| 准确性 | 可能过时或不准确 | 生成准确回答 |

**典型应用场景**：企业知识问答、法律咨询、医疗辅助、代码助手。

### 2.3 Tool Calling（工具调用）—— 让 AI 能"动手"做事

Tool Calling 允许 LLM 在对话过程中决定调用外部工具或 API 来完成任务，并将结果整合到最终回答中。

**工作流程**：

```
用户："帮我查一下深圳今天的天气，然后提醒我带伞"
  ↓
LLM 判断：需要"查询天气"这个工具
  ↓
生成调用参数：{city: "深圳", date: "today"}
  ↓
执行工具 → 返回：{weather: "阵雨", temp: 28°C}
  ↓
LLM 整合回答："深圳今天阵雨，28°C，出门记得带伞！"
```

## 三、AI 应用技术篇

### 3.1 什么是 AI Agent（智能体）？

AI Agent 是一个能够自主理解、规划并执行复杂任务的 AI 系统。它不只是回答问题，而是能"动手"帮你完成任务。

**四大能力**：感知环境、自主规划、调用工具、自我反思。

**工作流程**：任务拆解 → 工具调用 → 执行与迭代 → 交付结果。

### 3.2 什么是 MCP（模型上下文协议）？

MCP（Model Context Protocol）是一个开放标准协议，定义了 AI 应用（客户端）与外部工具/数据源（服务器）之间的标准化通信方式。

| | 没有 MCP | 有 MCP |
|--|----------|--------|
| 开发方式 | 每个 AI 应用都要为每个工具写定制代码 | 所有应用和工具通过统一接口即插即用 |

**架构**：AI 应用（客户端） ↔ MCP 标准协议 ↔ MCP 服务器（暴露工具、资源）↔ 外部系统（数据库、文件等）

> 一句话总结：Tool Calling 是"AI 知道怎么用工具"的能力，MCP 是"所有工具统一接口"的规范。

### 3.3 从 LLM 到 Agent 的进化路径

```
LLM（大脑）
  → LLM + Prompt（学会提问）
    → LLM + RAG（拥有知识）
      → LLM + RAG + Tool Calling（拥有手脚）
        → AI Agent（自主执行任务）
          → Agent + MCP（标准化连接万物）
```

## 四、完整示例：AI Agent 自动发送文章摘要邮件

**任务**："帮我从网上找三篇关于 AI 的最新文章，总结每篇核心观点，发到我的邮箱"

| 方式 | 流程 | 角色 |
|------|------|------|
| 传统方式 | 搜索 → 复制 → 粘贴 → 让 AI 总结 → 复制总结 → 发邮件 | 你是主导者 |
| Agent 方式 | 下达任务 → Agent 自动拆解、搜索、阅读、总结、发邮件 | Agent 是主导者 |

## 六、在 Trae IDE 中配置和使用 MCP

### 6.1 认识 Trae MCP

MCP（模型上下文协议）是一种允许大型语言模型（LLMs）访问自定义工具和服务的协议。在 Trae IDE 中，智能体作为 MCP 客户端，可以向 MCP Server 发起请求，使用它们提供的工具来增强任务执行能力。

简单来说，MCP 让 Trae 的 AI 智能体能够"调用外部工具"，从而完成更复杂的任务。

### 6.2 配置 MCP Server

**方式一：从 MCP 市场添加（推荐）**

1. 打开 TraeCode，点击设置图标，进入设置中心
2. 在左侧导航栏中选择 MCP
3. 点击"从市场添加"
4. 找到需要的 MCP Server，点击 + 按钮
5. 填入配置信息（如 API Key、Token 等），点击确认

**方式二：手动配置**

1. 进入 设置 → MCP
2. 点击"手动添加"
3. 填入 MCP Server 的 JSON 配置
4. 点击确认

**方式三：项目级配置**

在项目根目录下创建 `.trae/mcp.json` 文件：

```json
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-developer-mcp", "--stdio"],
      "env": {
        "FIGMA_PERSONAL_ACCESS_TOKEN": "your-figma-token-here"
      }
    }
  }
}
```

启用方式：前往 设置 > MCP > 打开"启用项目级 MCP"开关。

### 6.3 实战案例：Figma MCP —— 设计稿一键转代码

**第一步**：安装 TraeCode

前往 TRAE CN 官网下载并安装。

**第二步**：获取 Figma Access Token

1. 登录 Figma
2. 点击用户头像 → Settings
3. 选择 Security，找到 Personal access tokens
4. 点击 Generate new token，配置权限并复制 Token

**第三步**：添加 Figma AI Bridge

1. 打开 TraeCode，进入 设置 → MCP
2. 点击"从市场添加"
3. 搜索 Figma AI Bridge，点击 + 按钮
4. 填入 Figma Personal Access Token
5. 点击确认

**第四步**：使用 Figma MCP 生成代码

1. 在 Figma 中选中要实现的 UI 组件
2. 右键选择"Copy link to selection"
3. 在 Trae 聊天窗口中粘贴链接并输入指令
